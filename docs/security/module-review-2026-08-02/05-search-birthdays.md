# Модуль: Единый поиск, дни рождения

**Файлы:** `Modules.Medical/Search/*`, `Modules.Birthdays/*`,
`Infrastructure/Search/RussianTextSearcher.cs`, `RussianStemmer.cs`, `TrigramSimilarity.cs`

**Статус:** черновой список для дальнейшей обработки.

## Сводка

Оба модуля небольшие и чистые. `SearchService` — фасад над 4 источниками с раздельным контролем
доступа на КАЖДЫЙ источник (не единая проверка «на входе»): лекарства и дни рождения — по
`GetActiveFamilyIdsAsync`, мед-записи — переиспользуют `MedicalRecordService.SearchAsync` (тот же
инвариант видимости, что и в основном модуле мед-записей), справочник — глобально доступен по
определению (обезличен). Утечек между scope не найдено. `Birthdays`-модуль зеркалит паттерн
`Medications`/`Medkits` (роль Member, фильтрация по `FamilyId`) буквально один в один — отдельных
находок не появилось.

## 🟢 Низкий приоритет / на заметку

### 1. `GET /api/families/{familyId}/birthdays` не пагинирован

- **Где:** `Modules.Birthdays/Birthdays/BirthdayEndpoints.cs:11-16`,
  `BirthdayService.GetForFamilyAsync`.
- Возвращает все дни рождения семьи целиком за один запрос. При ожидаемых объёмах (дни рождения
  членов одной семьи — десятки, не тысячи записей) это не проблема; фиксируется на всякий случай,
  если сценарий использования когда-то изменится (например, «семья» станет крупной организацией).

## ✅ Проверено, проблем не найдено

- `SearchService.SearchAsync` — каждый из 4 источников (лекарства/справочник/мед-записи/дни
  рождения) скоупится независимо ДО похода в SQL/in-memory поиск; непрошенный источник вообще не
  трогает БД (экономия для дорогого in-memory поиска по мед-записям, который расшифровывает все
  видимые записи пользователя).
- Raw SQL в `SearchService.SearchMedicationsAsync`/`SearchKbAsync` — параметризован через
  `$"""..."""`-интерполяцию (`SqlQuery<T>`), `FamilyId`-скоуп (`m."FamilyId" = ANY({familyIds...})`)
  накладывается ДО полнотекстового поиска, не после — нет пути прочитать чужую семью через search.
- `BirthdayService`/`BirthdayEndpoints` — идентичный `MedicationService`/`MedkitService` паттерн
  контроля доступа (`FamilyRole.Member`, фильтрация по `FamilyId`), последовательно применён к
  Get/Create/Update/Delete.
- `RussianTextSearcher`/`TrigramSimilarity`/`RussianStemmer` — чистые функции без внешнего
  состояния и без операций с БД/файловой системой — поверхность атаки отсутствует.
