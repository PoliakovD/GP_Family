# Матрица прав доступа (этап 2, задача 2.4)

Роли контекста семьи: **Владелец** (OwnerUserId ресурса), **Admin** / **Member**
(активные члены семьи, `FamilyRole`), **Не-член** (посторонний или PendingApproval).
Оба провайдера входа (Telegram, PWA-cookie) дают одинаковые claims (`familyhub:user_id`)
→ права идентичны и определяются только данными.

## Медицинские записи (персональный ресурс)

Канон видимости — `MedicalRecordService.VisibleRecordsQuery`: запись видна, если
(а) ты владелец, ИЛИ (б) владелец расшарил свои записи семье (`FamilyMedicalShare`),
ты — активный член этой семьи, и запись не скрыта от неё (`MedicalRecordHidden`).

| Действие | Владелец | Admin семьи | Member семьи | Не-член |
|----------|:-:|:-:|:-:|:-:|
| Просмотр своих записей | ✔ | — | — | — |
| Просмотр чужих (при share, не hidden) | — | ✔* | ✔* | ✖ |
| Создание записи | ✔ | ✖ | ✖ | ✖ |
| Share/Unshare своей коллекции | ✔ | ✖ | ✖ | ✖ |
| Hide/Unhide записи | ✔ | ✖ | ✖ | ✖ |
| Вложение: загрузка | ✔ | ✖ | ✖ | ✖ |
| Вложение: скачивание | ✔ | ✔* | ✔* | ✖ |
| Просмотр показателей/резюме/заключения записи (`GET .../indicators`, `.../summary`, `.../conclusion`, статья справочника по показателю) | ✔ | ✔* | ✔* | ✖ |
| Редактирование записи, смена источника (`PUT .../specimen`, `PUT .../specimen-pending`) | ✔ | ✖ | ✖ | ✖ |
| Добавить/изменить/удалить показатель (`POST .../indicators`, `PUT/DELETE /api/indicators/{id}`) | ✔ | ✖ | ✖ | ✖ |
| Запуск распознавания (`POST .../extract`), пересчёт резюме (`POST .../summary/regenerate`) | ✔ | ✖ | ✖ | ✖ |
| Удаление записи (вместе с её задачей распознавания) | ✔ | ✖ | ✖ | ✖ |

\* — фиксируется в журнале аудита (`audit.MedicalAccessAudits`, задача 2.7).
Инвариант 2: даже Admin семьи не управляет чужим шарингом.

| Действие | Admin | Member | Не-член |

| Инвайты: создание/отзыв, approve/reject | ✔ | ✖ | ✖ |
| Выгон участника | ✔ | ✖ | ✖ |

| Удаление семьи | ✔ | ✖ | ✖ |

ушедшего (этап 1).

## Служебные эндпоинты пользователя

| Эндпоинт | Кто | Что видно |
|---|---|---|
| `GET /api/ai/status` | любой аутентифицированный (согласие ПДн не требуется — медданных нет) | только `{available}` |
| `GET /api/jobs/active-summary` | аутентифицированный + согласие | **только свои** активные задачи (`RequestedByUserId`), метки записей; задачи удалённых записей не показываются |
| `GET /api/home/summary` | аутентифицированный + согласие | сводка по своим семьям: лекарства, заявки на вступление (только Admin семьи), дни рождения, «В порядке» |
| `/internal/bot/*` | только процесс бота (`X-Internal-Token`) | контракт бота с API, снаружи закрыт (ADR-0008) |

## Предусловия любого доступа

1. Аутентификация (FallbackPolicy — всё закрыто по умолчанию; исключения: auth,
   consent-тексты, политика, скачивание по подписанной ссылке).
2. Принятое актуальное согласие ПДн — для модулей Medical и Birthdays
   (`ConsentRequiredFilter`).
