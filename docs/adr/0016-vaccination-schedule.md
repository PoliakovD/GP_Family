# ADR-0016. Прививки: вычисляемый график по каталогу, общая точка доступа с курсами приёма

**Статус:** принят. **Дата:** 2026-09-27. Переиспользует модель доступа [ADR-0015](0015-medication-dose-reminders-push-actions.md)
(курсы приёма лекарств), приём токена-хеша из [ADR-0014](0014-doctor-report-public-link.md), текстовые
ограничения [ADR-0004](0004-web-push-egress-exception.md).

## Контекст

Четвёртый подпункт «Здоровья» (после аптечки, приёма лекарств, дневника/отчёта). Референс —
`.claude/uirework via claude design/Screen - Vaccination.dc.html`. Ключевое отличие от предыдущих
медицинских фич: у прививки есть **известный заранее график** (национальный календарь РФ, приказ
Минздрава №1122н) — в отличие от курса лекарств или анализа, где нет «календаря по умолчанию».

## Решение

### 1. График вычисляется, а не хранится
`VaccineCatalog` (`FamilyHub.Domain.Vaccinations`) — статический справочник серий вакцин (национальный
календарь, взрослые ревакцинации, эпидпоказания), стиль `HealthMetricCatalog`: стабильные коды серий,
не переименовывать. `VaccinationScheduleCalculator.Calculate(birthDate, facts, today)` — чистая функция
(как `DoseScheduleExpander`), строит статус каждой дозы (`Done/HadDisease/DueSoon/CanDo/Upcoming/NoData`)
из даты рождения человека и уже внесённых фактов. В БД (`Vaccination`) хранятся только факты —
`SeriesCode`+`DoseIndex` (или `CustomName` для прививки не из календаря), `Kind`, дата. Ничего похожего на
«будущие приёмы» `MedicationDose` не материализуется вовсе — график каждый раз считается заново.

**«Нет данных» ≠ «пропущено».** Окно, закрывшееся больше года назад без единого факта, получает
`NoData`, а не тревожный `CanDo` с первого дня использования — взрослые редко помнят детские прививки
(макет, раздел «UX-решения»). Ответ «не помню» (`VaccinationKind.Unknown`) — тоже `NoData`, но явно
зафиксированный: UI не переспрашивает то же самое повторно.

**Эпидемические серии добровольны.** Клещевой энцефалит, гепатит A и т.п. не показываются в графике,
пока пользователь не внёс первую дозу сам — иначе у каждого человека сразу висело бы полтора десятка
незаполненных пунктов. После первой дозы следующие идут по интервалу от предыдущей ФАКТИЧЕСКОЙ даты
(не от рождения) — там нет «календарного» срока, курс начинается, когда человек решил.

**Повторы взрослых** (АДС-М каждые 10 лет, клещевой энцефалит каждые 3 года после
`VaccineSeries.RepeatEveryYears`) генерируются по одному — только ближайший неотмеченный, не бесконечный
хвост будущих дат. Грипп — не через `RepeatEveryYears`, а через календарный сезон
(`VaccineSeries.SeasonalWindow`): доза, сделанная в любой момент между началом одного сезона и началом
следующего, засчитывается на весь год.

### 2. Доступ — общая точка с курсами приёма, не копия
Прививки используют **тот же трёхканальный доступ**, что курсы (свой / подопечный активной семьи —
полностью / наблюдаемый взрослый — только чтение), и ту же таблицу `MedicationWatcher` («кто следит за
человеком» — понятие не привязано к лекарствам, переименовывать таблицу не стали). Raw-выборка (активные
семьи, где я админ, за кем слежу) вынесена в `SubjectScopeService` — `MedicationCourseAccess` теперь
только оборачивает её в `CourseScope`, `VaccinationAccess` — в `VaccinationScope`; поведение курсов не
изменилось (регрессия проверена всем набором их тестов).

### 3. Сертификат — фото сохраняется, в отличие от разового OCR
`MedicationOcrService` (фото упаковки препарата) никогда не сохраняет фото — оно нужно один раз, чтобы
заполнить поля формы. Здесь наоборот: макет явно требует «файл сохранится у каждой найденной прививки».
Поэтому распознавание — в два шага: `POST /certificate/recognize` (синхронно, ничего не сохраняет,
как `MedicationOcrService`) → пользователь правит найденное → `POST /certificate/confirm` (то же фото
пересылается второй раз) сохраняет `VaccinationCertificate` + файлы + N записей `Vaccination`, у всех —
общий `CertificateId` (файл не копируется на каждую находку). Сопоставление найденного текста с каталогом —
простое нормализованное вхождение по названию/торговым названиям (не триграммы/веб-поиск, как у
справочника препаратов: сравниваем с полутора десятками известных серий, не с открытым множеством).
`DoseIndex` эта эвристика не назначает — фронт сам подставляет ближайшую неотмеченную дозу найденной
серии по уже загруженному графику человека.

### 4. Тексты уведомлений — без названия вакцины/инфекции (как ADR-0004/ADR-0015)
`VaccinationReminderJob` (ежедневно) шлёт «Скоро прививка» / «Можно сделать прививку» — то же самое
«за 2 недели до срока и если срок прошёл», что ADR-0015 для лекарств. Дедуп-ключ не зависит от даты
прогона (только человек+серия+доза), поэтому пропуск одного дневного тика не теряет напоминание, а
многодневное окно `DueSoon`/`CanDo` не шлёт его повторно.

### 5. Реакция — через дневник, но только для своих
Пользователь предложил записывать реакцию в дневник подопечного — решение (сентябрь 2026): дневник
остаётся строго личным (`HealthNote.OwnerUserId`, без изменений схемы), поэтому «Записать
температуру/симптом» после сохранения прививки доступно только для своих прививок; для подопечных —
только текстовая подсказка, когда ждать реакцию. Связь прививка↔дневник не хранится отдельным полем —
вычисляется по совпадению дат (запись дневника в окне `[дата прививки, +ReactionWindowDays]`), тем же
приёмом, что `DoctorReportDataCollector` сопоставляет назначения из визитов с приёмами дневника.

### 6. Отчёт врачу и справочник
`DoctorReport.IncludeVaccinations` — седьмой блок, тот же паттерн из шести булевых галочек (не список
ключей), что и остальные пять. Справочник (`/health/kb/vaccines`) — статические карточки каталога, без
ИИ-обогащения (как и решение не путать со справочником препаратов/анализов, у которых есть весь
enrich-конвейер — тут закрытое множество серий, KB не нужен).

## Последствия
- Национальный календарь — приближение (возрастные окна округлены до месяцев/дней), не медицинское
  назначение; перед использованием в проде стоит свериться с актуальной редакцией приказа №1122н.
- `Vaccination`/`VaccinationCertificate` без FK на `User` (как `MedicationCourse`/`HealthNote`) — чистка
  при удалении аккаунта/подопечного явная (`AccountService`/`FamilyDependentService`), включая их
  FK-less `FileAttachment`-строки.
- Наблюдатель за взрослым видит вычисленный график, но не может ничего отметить — Watch-доступ read-only,
  как у курсов.
