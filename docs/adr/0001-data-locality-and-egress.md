# ADR-0001. Локализация данных в РФ и контур исходящего трафика

**Статус:** принят (этап 2, задача 2.1). **Дата:** 2026-07-22.

## Контекст

FamilyHub обрабатывает специальную категорию ПДн (медицинские данные) граждан РФ.
152-ФЗ требует локализации баз ПДн на территории РФ; передача медданных зарубежным
LLM-API недопустима.

## Решение

1. **Хранение данных — только РФ.** PostgreSQL (все схемы: identity, medical, kb, audit),
   MinIO (шифрованные вложения) и Seq размещаются на серверах на территории РФ.
   Размещение фиксируется в договоре с хостинг-провайдером; при смене провайдера —
   новый ADR.
2. **LLM — только локальный контур.** Обработка медданных ИИ-моделями выполняется
   исключительно локальным Qwen через LM Studio (`LmStudio:BaseUrl` — адрес приватной
   сети, не публичный интернет). Фото упаковок не сохраняются (см. `MedicationOcrService`).
3. **Запрет исходящих вызовов к зарубежным LLM-API — на уровне сети.** Egress-политика
   хоста (firewall/nftables или security-group облака): исходящий трафик API-контейнера
   разрешён ТОЛЬКО к:
   - PostgreSQL / MinIO / Seq / LM Studio (приватная сеть);
   - `api.telegram.org` (бот и Mini App — функциональная основа продукта);
   - SMTP-хосту российского email-провайдера (задача 2.5, `Email:Providers`);
   - push-релеям браузеров (FCM/Mozilla/Apple) — именованное исключение, см.
     [ADR-0004](0004-web-push-egress-exception.md): через них проходит только обобщённый,
     RFC8291-шифрованный payload, без ПДн;
   - `searchapi.api.cloud.yandex.net` (активный провайдер, `Enrichment:Provider=Yandex`) и
     `api.search.brave.com` (поддерживаемая альтернатива, не используется по умолчанию) — именованное
     исключение, см. [ADR-0005](0005-medication-enrichment-egress.md): по умолчанию (`Provider=Null`)
     egress не активен ни для одного из них; когда активен — через него проходит только
     нормализованное название препарата, без user/family-контекста; суммаризация найденного
     материала остаётся строго на локальном Qwen (см. п.2 ниже) независимо от провайдера.
   Всё остальное — deny by default. Правила версионируются в инфраструктурном
   репозитории/скриптах провижининга (ops-артефакт, вне этого репо).

## Чек-лист для новых внешних зависимостей

Перед добавлением любого исходящего вызова (SDK, webhook, CDN):
- [ ] Сервис размещён в РФ? Если нет — проходит ли через него ПДн? (при «да» — стоп);
- [ ] добавлено правило в egress-политику;
- [ ] обновлён этот ADR (раздел «Решение», п.3).

## Последствия

- Никакие облачные LLM (OpenAI/Anthropic/Google) не могут быть подключены без
  пересмотра этого ADR — даже «только для нечувствительных данных».
- Суточные лимиты локальной модели компенсируются очередями конвейера (этап 4),
  а не выносом обработки в облако.
- Ограничение single-instance: in-memory счётчики (лимиты SMTP-провайдеров,
  rate limiting) корректны при одном инстансе API; горизонтальное масштабирование
  потребует выноса счётчиков в Postgres/Redis (РФ-контур).
